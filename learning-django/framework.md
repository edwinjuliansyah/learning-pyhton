# Konsep Web Framework & Three-Tier Architecture

* **WEB FRAMEWORK PARADIGM**: Logika arsitektur yang menyediakan fondasi struktural (*scaffolding*) standar untuk aplikasi web. *Mengapa digunakan:* Mencegah *developer* "menciptakan ulang roda" (*reinventing the wheel*) untuk fungsi-fungsi dasar (seperti keamanan, *routing*, dan koneksi database). Ini memastikan kode lebih rapi, terstandarisasi, dan sangat mempercepat siklus pengembangan produk (*concept to completion*).

* **DJANGO CORE ADVANTAGES**: Django adalah framework Python berskala tinggi yang mengusung filosofi "batteries-included" (fitur bawaan lengkap). *Sebab-akibat:* Karena Django sudah mengemas fitur krusial secara bawaan (*out-of-the-box*)—seperti sistem autentikasi, panel admin, dan *middleware* keamanan penangkal serangan siber—*engineer* dapat langsung fokus menulis logika bisnis aplikasi yang unik tanpa harus merakit infrastruktur keamanan dari nol.

* **THREE-TIER ARCHITECTURE**: Pendekatan arsitektur modular yang memecah sistem perangkat lunak menjadi tiga lapisan logis yang terisolasi: *Presentation Tier* (UI/Front-End), *Application Tier* (Logika Back-End), dan *Data Tier* (Database). *Tujuan:* Menciptakan pemisahan tanggung jawab (*Separation of Concerns*). Jika ingin mengganti database tidak perlu merombak kode UI, begitu pula sebaliknya.

* **APPLICATION TIER (THE MIDDLEMAN)**: Jembatan komputasi utama dalam arsitektur tiga tingkat. *Logika operasional:* Lapisan ini tidak menampilkan visual antarmuka dan tidak menampung penyimpanan permanen. Tugas murninya adalah menerima *request* dari *Presentation Tier*, memproses logika bisnis/algoritmanya, lalu menginstruksikan *Data Tier* untuk menyimpan atau mengambil data yang dibutuhkan.

* **LOGICAL VS PHYSICAL TIERS**: Perbedaan kritis dalam konsep penyebaran sistem (*deployment*). *Insight arsitektur:* Ketiga tingkat (Presentation, Application, Data) adalah partisi **logis**, bukan fisik. *Edge-case:* Di awal fase pengembangan atau aplikasi berskala kecil, ketiga *tier* ini sangat bisa berjalan berdampingan di dalam **satu server fisik/mesin yang sama**. Pembagian ke server fisik yang berbeda-beda biasanya baru dilakukan ketika aplikasi butuh untuk di-skala (*scaling*) akibat lonjakan trafik.
